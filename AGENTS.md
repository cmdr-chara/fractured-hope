# Fractured Hope agent instructions

## Content and framework boundaries

- Keep authored story/canon work separate from Quartz framework, theme, and publishing changes. A technical cleanup must not rewrite character facts, chronology, relationships, or narrative voice.
- Preserve existing content language, frontmatter, aliases, wikilinks, slugs, and references. Do not fill unresolved lore with invented canon or silently reconcile contradictory source material.
- `content/meta/story-audit.md` is generated by `scripts/generate-story-audit.ts`. Change the generator or its real inputs, not the report to manufacture a clean result.
- The story audit scans every Markdown file under `content/`. Keep agent instructions, temporary task notes, and maintenance checklists outside that tree unless their publication and audit treatment are intentional.
- Preserve upstream Quartz licensing and distinguish framework documentation from this story's authoritative source material.

## Task-specific guidance

Use [docs/CONTENT_CONTRACT.md](docs/CONTENT_CONTRACT.md) for story edits and [package.json](package.json) for the actual toolchain/scripts. `npm run story:audit` regenerates the story report; `npm run check` also invokes it through `precheck`. Review that generated diff rather than treating validation as read-only.

Use focused checks for the affected content or framework surface; `npm test` covers Quartz tests. Builds and plugin installation may need network access. Do not mistake a generated audit or a successful build for editorial approval or a published website.

Completion requires relevant links/structure and authored intent preserved, generated changes reviewed, and verification limits stated. Site publication is a distinct operation; ordinary repository edits do not authorize rewriting canon or disclosing unpublished material.
